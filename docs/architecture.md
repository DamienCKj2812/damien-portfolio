# Runtime architecture

`src/main.tsx` mounts `App` in StrictMode. `App.tsx` lazy-loads `CityWalkthrough` and mounts persistent `BackgroundMusic` alongside it; the older static sections/header/footer and keyboard viewer are not mounted.

All areas share one demand-rendered Canvas with capped DPR. Blender coordinates are Z-up; both camera poses and geometry receive the same Y-up basis conversion. Finite departures and autonomous city/room clocks invalidate only while their area is active and visible.

The lobby, Skills gallery and Projects hallway use dark planar floor reflections of their real WebGL geometry, including native NPC poses, exhibit panels and lights. Reflection targets are capped at 512² pixels on desktop and 256² on narrow viewports, with slight shader softening and angle-dependent attenuation. Floor planes sit just above the authored floor surfaces and below tile joints; the upper lobby deck uses its own 6.12 m elevation. Reflection passes hide other reflectors to prevent recursion, temporarily correct point sizing for the smaller target, and restore render target, viewport, scissor, XR/shadow state, visibility and particle uniforms in `finally`. Targets/materials/geometry are disposed on unmount or resolution changes. Reflections follow existing rendered frames and do not create an idle animation loop or intercept picks.

## Type and content boundaries

The 61 original application modules now use TS/TSX, alongside shared type modules; the 31 existing Node tools use MTS with shared JSON/browser helpers and verification aggregators. `npm run typecheck` checks app and tooling separately with strict TypeScript 6.0.3 and `skipLibCheck: false`; Vite remains responsible for browser transpilation/builds. Further `noUncheckedIndexedAccess` / `exactOptionalPropertyTypes` hardening is ongoing.

`src/data/portfolio.json` owns authored identity, Observer, contact, music and record data. `src/data/portfolio.ts` validates that JSON through the portfolio parsers and combines it with the generated portrait manifest. Node Skills/timeline generators and Python contact-card tooling read canonical JSON directly, replacing source-text VM/regex extraction. Content provenance hashes the JSON bytes rather than the TypeScript facade. Generated scene manifests and binary descriptors remain runtime-validated at the loader boundary; types do not replace buffer/stride/hash checks.

Node MTS tools run with `node --import tsx <path>.mts`. `scripts/node_json.mts` shares JSON loading, and `scripts/browser_tools.mts` shares declared Playwright, Chrome selection and screenshot output. Its browser init-script helper supplies `tsx`'s serialized `__name` support before instrumented callbacks execute. See [development](development.md) for check groups and environment overrides.

## Clocks and loading

`App` mounts a single reference-inspired startup loader before the lazy city runtime is available. The same overlay stays mounted while `CityWalkthrough` validates/downloads city geometry, animation channels and textures, journey metadata, lobby/cabin and all four room packages. A two-worker destination queue bounds parallel downloads/texture decoding. The cache is reused on floor selection; both portrait layers and project posters are decoded ahead of their first display. Progress is weighted completed preparation milestones, not an elapsed-time animation or a claimed byte-download percentage. Once preparation and the first actual Canvas draw are complete, the loader shows 100% and **Starting your journey…** for one additional second. Journey input, underlying DOM controls, scene motion and audio remain gated until that handoff. The finite delay cancels/resets on error, Retry or unmount; it never determines progress or adds a perpetual animation loop.

Critical startup failures show Retry in the same screen; optional package/image/audio failures are marked unavailable and preserve the existing sealed chapter/room Retry flow. Abort controllers, prepared texture disposal and stale-completion guards cover Retry/unmount/StrictMode. Music buffers through the persistent audio element's `preload="auto"`; the effects engine caches encoded bytes without constructing Web Audio. Audio readiness is reported but does not hold the city hostage. The sound-choice dialog and remembered playback attempts start after scene readiness. Actual project videos remain selectively loaded for visible previews and focused walkthroughs.

The top-left branding is `portfolio.siteTitle` (`DamienCKJ portfolio`). Icon-only preferences and help buttons sit together in the top-right action group, immediately left of Choose a floor, and remain available in rooms. `ToplineControl.tsx` gives them silent hover/focus tooltips with Escape dismissal and accessible descriptions. The floor shortcut becomes icon-only on narrow screens. Help opens a React adaptation of `Guide Overlay.dc.html`: scroll/swipe, drag-to-look and click-to-inspect demonstrations with a radial instrument, step indicators, keyboard controls and a blurred live-scene backdrop. It uses the existing scene rather than a second Canvas or static screenshot. Background controls and the custom cursor are hidden while the native guide modal is open.

`CityWalkthrough` suspends journey gestures and supplies a derived paused/input-blocked room state without changing the saved room state. Native modal focus containment/restoration prevents interaction behind the guide. Demo RAF updates are capped at 30 FPS, cleaned up on close/unmount, suspended on hidden pages and disabled with reduced motion. Buttons use delegated system-click audio; automatic progression and hover/focus are silent.

Background music uses one HTML audio element outside the changing journey/room components. `portfolio.music` owns the title, creator, public asset path, default 35% volume and credit URL; the canonical MP3 lives under `assets/media/audio/music/`, with an exact-byte browser copy synced to `public/media/audio/music/` before dev/build. Shared media provenance and hashes live in `assets/media/manifest.json`; URLs use Vite's base path. The first visit opens the full-screen native **ENTER WITH SOUND?** modal, matching `Sound Prompt.dc.html` with a blurred live-scene backdrop, city-poster loading fallback, JetBrains Mono and five CSS sound bars. YES/Enter calls `play()` and unlocks Web Audio directly during the user's trusted activation; MUTED/M/Escape silences both channels. `damien-portfolio:audio-consent` remembers the resolved choice, so refresh/return skips the modal and restores independent channel settings. Remembered enabled music probes browser autoplay permission once through `autoplayPolicy.ts` and the media play promise. A blocked policy remains ready until a real gesture; a successful autoplay authorizes normal visible-page resume. The native dialog traps/restores focus and keeps journey keyboard gestures local; reduced motion freezes the sound bars and fallback transition.

The preferences icon reuses `AudioConsentDialog.tsx`'s original full-screen YES/MUTED design. `SoundEffectsProvider` owns its open/close state; `CityWalkthrough` derives the same paused/input-blocked room state used by the guide without changing the user's previous pause settings. Choosing saves the decision and closes the prompt; native focus returns to the preferences icon, and Help/Preferences cannot stack. Playback cleanup runs on actual unmount or disable, so a consent update cannot inadvertently pause an already-playing track.

The compact transparent panel has independent Music and SFX toggles, a sound-bar icon and an uppercase music-note/title/creator credit. It uses the configured fixed mix without volume sliders. After choosing muted, either channel can be enabled independently through its corner control, or both can be enabled through the preferences prompt. Preferences persist in `localStorage`; music buffers silently during startup while playback remains gated by readiness and consent/browser policy. Playback loops without restarting on floor changes, pauses while the page is hidden and resumes when visible after successful autoplay or a current-page user activation. Native play promises are guarded against stale attempts, controls remain usable if storage fails, and unmount cleans up event listeners/playback.

Scoped `:has(.city-controls:not([hidden]))` rules raise the audio panel above visible city/room progress controls. With no progress bar, such as the stationary About room, the panel returns to its bottom-right corner. No polling, resize subscription or extra scene invalidation is required.

Executable sources of truth are `assets/journey/room-destinations.json`, generated `public/models/journey.json`, scene manifests, and runtime code.

- City frames 1–383 hand off through a 60-frame blend into lobby frames 1–1020; lobby global end is 1403.
- City flying/road vehicles, ten configured walking NPCs and the explicitly autonomous rear-highway maglev run on an independent clock while the city is visible, without wheel/timeline input. Cars and walkers shuttle along native routes with eased end turns; walking gait follows travelled distance and settles during turns. The rear train's exported `motion` descriptor selects a fixed-heading one-way pass: 2000 clock frames of movement along its extended route, then 60 hidden reset frames. The runtime combines `motion.visible` with native actor visibility; reset endpoints are authored outside all camera views, so the train never spins in front of the viewer. The foreground left-side maglev and entrance doors use the scroll-driven journey frame. Hidden/offscreen city and reduced-motion preferences suspend the autonomous clock, and reverse navigation resumes its prior phase without a hidden-time jump.
- City suspended/sky dots export as a separate `points` group with the `sky` role. Their GPU point shader derives varied sizes, brightness, blink speeds and phases from stable position-based seeds. Twinkling follows the visible-city clock and freezes for reduced motion; people, foliage and other point groups retain their regular materials.
- Three shooting stars use fixed Blender Z-up routes above the city, with different delays, durations and 11/14/17-second repeat periods. Bright heads and tapered, fading billboard trails share the autonomous city clock, independent of scroll. Meteor geometry/materials are cached and disposed on unmount; the effect adds no separate timer, renderer or invalidation loop and suppresses meteors for reduced motion.
- Cabin entry starts at local 62 and reaches selection at local 180 / global 1521. Selected departure uses local 181–510; the final 414–510 segment blends into the destination view.
- `elevatorTiming.ts` sets elevator transitions to 2× playback: departures take about 5.5 seconds, return turns/walks run twice as fast, and cabin entry requires half the scroll distance. The entry mapping is reversible across its boundary; the city/lobby scroll pace and room-tour clocks retain their own timing. Loading holds still stop before unopened interiors.
- Startup fetches city and journey configuration. Lobby preload starts at global 100; geometry reveals and holds for load at 245. City geometry hides at 383 independently of the camera blend.
- Cabin preloads at global 893 and reveals/holds at 1283. Rooms load on selection and hold departure at local 296, before the doors open. Failed requests offer Retry/cancel.
- Loaded packages remain cached for reverse navigation and repeat visits. This staged behavior is distinct from the [planned complete-preload feature](roadmap.md).

The preloaded lobby is clipped to the generated `lobbyPortal` street aperture while the camera remains outdoors. `lobbyPortal.ts` updates four world-space planes on existing demand frames; point, line, solid and reflection shaders share those planes. Entering clears the limits without changing their count, and reversing restores them. This prevents the lobby's wider black walls from covering the city skyline before entry. The city integration separately removes curved tower-skin geometry inside the atrium so it cannot obscure the left/right lobby balconies during the camera handoff.

## Room behavior

| Room | Movement / animation | Interaction |
| --- | --- | --- |
| About | Computer-centered authored home camera; fixed-position 360° free-look and contact focus | Mouse/touch/arrow-key look, R/reset; desk-card contact focus; Observer Identity/Portrait/Record dialog |
| Skills | Non-looping 2940-frame position route; independent 959-frame loop of 90 articulated visitor-part channels in reserved lanes | Nine approved About/Projects-backed skill cards, Projects' shared v2 focus/case-file UI and evidence menus; preserved outlined AT-AT, manual look and look-preserving station jumps |
| Projects | Fixed-axis movement; 1200-frame independent native morph/transform loop | 16 catalogue-backed displays across Client, Academic and Personal; two automatic holographic portals; top-right category label; featured FYP; expandable reviewed details and repository links |
| Experience | Looping 2400-frame position route; independent globe/planet clock; no NPCs | Six cards/nodes, globe/roof/window detail views |

Exhibit jumps preserve look. Room alignment rotates local +Y by π and translates the entrance anchor to the cabin threshold. Scene gestures are disabled during departure/room visits, so their controls own input.

Skills card prompts reuse the About office's floating-label and corner-bracket style. They show the authored category and skill list when a card occupies the centre of the view or is hovered, with a keyboard/touch action selecting its existing sidebar details. Only one prompt is shown; cards behind the player or occluded by the AT-AT/architecture are excluded. Prompt projection and cached occlusion checks use existing camera/hover frames, and prompts clear during non-main views, departures and return dialogs. Hover/focus are silent; accepted label clicks use the environment sound convention.

Wheel/touch input in the two guided rooms updates a target route frame; a critically damped spring advances the displayed frame continuously rather than jumping the camera for every scroll event. Consecutive gestures accumulate against that target, including direction reversals. Explicit station/range/Home seeks retain their precise authored frame, and reduced motion uses direct positioning. The spring invalidates while settling and freezes offscreen or behind a modal. Skills visitor poses follow the displayed route frame; observatory planet time remains independent.

Skills, Projects and Experience share the city's full-width bottom progress-bar styling through `RoomProgressBar.tsx`. Guided progress uses the player route's frame bounds (not the animation loop); Projects uses its hallway Y limits and rendered camera position. Scrubbing seeks the route or hallway movement, preserving look direction. Projects' walking, scroll and progress seeking share overall bounds via `hallwayCategories.ts`; automatic portals add no collision stops. Progress updates come from the demand-rendered camera callback, remain visible with a collapsed room menu, and hide during detail views, dialogs and return transitions. The stationary About office has no progress bar.

Projects opens directly into Client / real world project. Academic and Personal have open holographic portals: framing/curtain/lettering groups reveal after preceding displays, and independent transparent materials soften near the camera. There are no portal picks, activation buttons, leaf animation, timers or collision pauses. `RoomNavigator` moves continuously; the existing camera callback derives category visits and updates `HallwayCategoryLabel` at the top right, including reverse movement and a hidden menu. `build_project_catalogue.py` derives the 16 exhibits from `docs/project-catalogue.md`; selected sidebar details retain full reviewed Markdown, contribution qualifications, code diagrams, evidence tables and explicit links. The catalogue itself stays unchanged.

Project card selection enters `view: 'project'` with `projectExploring: true`, opening both sidebars directly. `projectCardFocus.ts` fits the exported card mesh plus its brackets into the usable viewport; the shared camera eases into a front-facing pose and a responsive projection offset. `RoomNavigator` reports projected-corner framing/settling in the stage dataset. `ProjectCardFocusControls` presents the selected catalogue section in a fading translucent left column and section navigation on the right, retaining the card in the middle. Wheel-down advances sections and wheel-up reverses them, with a 60-pixel threshold and 400 ms cooldown; the first/last sections clamp. Long descriptions retain native scrolling until their directional boundary. Wheel navigation is silent and ignores dialogs, form fields, horizontal gestures and zoom gestures. Mobile uses a selector and reading dock. Hidden project visitors suspend; resources settle without an idle render loop. Back/Escape returns directly to saved hallway navigation, and camera view offsets clear on exit/unmount. The guide dialog keeps ownership of its own Escape handling. The two entrance directory/introduction panels are decorative rather than selectable project exhibits.

The browser loader reparameterizes the Level 2 and Level 4 routes by cumulative travel distance (`linearRoomRoute.ts`). Equal scroll increments therefore produce equal walking distance, including through all points of interest, with no inspection holds or arrival slowdowns. Skills keeps its 98-second non-looping endpoint and visitor clock coupled to walking; the observatory keeps its continuous 80-second loop and independent planet clock. Exhibit/station jump frames are remapped to their positions on the distance-based paths. Generated source packages retain the original authored samples.

`cameraMotion.ts` supplies velocity-preserving spring updates and shape-preserving cubic interpolation. `readRoomRoute` and `readCameraPose` interpolate between native samples each rendered frame, preserve integer-frame poses, and avoid position overshoot. Elevator playback eases into motion and settles at its endpoints; its cabin-to-room walk shares a continuous-velocity doorway waypoint. Return turns/walks use quintic easing with gentler acceleration, then look directly at the floor panel. These are runtime camera changes; authored animation samples and package descriptors remain the sources of truth.

### Returning to the elevator

Each floor has a visible rear elevator entrance aligned flush with its authored entrance anchor. The 2.6 × 3.2 m surround, jambs and sill overlap full-height door leaves to close perimeter/threshold gaps. `RoomElevatorEntrance` provides a generous door pick volume and a normal wall-mounted call button beside the doorway. A floating **ELEVATOR / Return to elevator** label and corner brackets use the same visual style and camera vertical-center focus rule as the About office targets. Alignment controls only this label: the physical call button has a larger 0.84 × 0.24 × 1.0 m invisible hit volume and remains clickable from off-center views. Clicking/tapping the doors, call button or focused label starts the return directly; the label also supports keyboard activation. Camera drags are rejected as clicks; profile/detail views and return dialogs disable the targets. The shared entrance clears during arrival/return transitions and its label projections use existing demand-rendered frames without an independent animation loop.

A backward wheel gesture first rewinds toward the entrance: guided route frame 1, the hallway's `minY`, or the office's main view. A further backward gesture at that boundary opens **Return to elevator?**; simply reaching it does not leave the room. Scrolling a sidebar stays local to its list. Home followed by Page Up is the keyboard equivalent. On touch screens, vertical swipes move along the room route (swipe down to go back); horizontal-led drags retain free-look.

The native confirmation dialog freezes room motion and traps/restores focus. Stay/Escape preserves the room view and resumes its previous pause settings; a short cooldown ignores leftover wheel momentum. Confirming sets the elevator to `returning`, disables room interaction, and hides its sidebar. `RoomReturnJourney` captures the live camera, turns toward the cabin, walks to its doorway, and reverses local elevator frames 414–180. The camera faces into the cabin during entry, then turns directly toward the floor buttons and holds that selection view while the doors finish closing behind it. Room geometry remains visible through entry and packages remain cached. The return invalidates only while active/visible and stops at completion; reduced motion completes the return without the animated walk.

The city timeline and direct floor shortcut are hidden during room visits/returns so they cannot bypass the doorway return. The sidebar includes an entrance-scroll hint; collapsing it to the Info tab leaves canvas gestures active.

## Native browser representation

Export point-source vertices and curve centerlines rather than realized Geometry Nodes spheres. Dark occlusion, surfaces, and typography are triangles; billboard screens also carry UV/textures. Native point/line behavior is not preserved by an ordinary GLB alone.

Camera/actor channel strides are **10 for city**, **12 for elevator/Skills**, and **16 for lobby/About/Projects/Experience**. Stride 12 carries pose, lens, and visibility; stride 16 adds four morph slots. Lobby NPCs use an independent visible-zone clock with 1019 unique frames; lobby camera and door channels still follow journey progress. Manifests describe group offsets and optional morph buffers/XYZ routes. Re-export every related buffer, descriptor, texture, and hash together.

The Observer's transparent `observerPick` volume is generated from the actual office figure. The modal keeps the previous office/card camera view, blocks background room input, and restores focus/scroll. Profile, portrait, skill-list, and record content comes through `src/data/portfolio.ts` from canonical `src/data/portfolio.json` and the generated portrait manifest.

### Pixel-grid portrait

The About profile's portrait is a static processed version of the original photograph, owned by [assets/portrait](../assets/portrait/README.md), separate from the office's point-source Observer. A Python image build removes the studio background, softly preserves monochrome photographic detail, applies one highlight-compressing tonal curve throughout the photo, and adds a faint grid. A generated image manifest supplies its hash for browser cache-busting.

`PixelPortrait` displays the normally scaled monochrome grid image by default. Fine-pointer movement reveals the aligned original-color photograph only through a local SVG pixel-cell mask, leaving a 700 ms fading trail; keyboard focus reveals the full photograph. Both public PNGs and hashes are generated together; the original layer has no tonal curve, grid or photographic blur. Reduced motion keeps the local brush but removes the fading trail. Leave/blur/hidden/offscreen/closing restore the default; unmount removes listeners and pending animation frames. Touch does not latch hover, and image-load failure preserves the default portrait. The portrait cursor is an outlined square without difference blending; clickable UI keeps its normal Click morph. Room clocks continue to pause behind the profile. Frames are scheduled only while old trail cells fade, settling once just the stationary brush remains; the effect has no canvas, WebGL context or scene invalidations.
