# Repository guidance

## Commands
- Use Node 22 LTS, version 22.13+. CI uses npm: `npm ci`, then `npm run lint && npm run typecheck && npm run build && npm run verify`; deployment consumes `dist/` and runs neither Blender nor browser automation. Maintain both npm and pnpm lockfiles; npm/`package-lock.json` is the CI authority.
- Focused lint: `npx eslint src/components/CityWalkthrough.tsx` (replace with changed TS/TSX/MTS paths). `npm run typecheck` checks app and Node tooling with TypeScript 6.0.3; there is no configured unit-test runner. ESLint has browser TS/TSX and Node MTS scopes; keep app source free of JS/JSX.
- `npm run verify` runs 20 non-browser checks. After browser-package changes, run `node --import tsx assets/journey/verify_rooms.mts`; source/export checks and model-specific commands are in the scoped asset guides. Execute Node MTS tools with `node --import tsx <path>.mts`.
- After a build, `npm run verify:browser` runs eleven actual-browser checks using declared Playwright 1.61.1. `CHROME_EXECUTABLE` overrides `/usr/bin/google-chrome`; `VERIFY_OUTPUT_DIR` overrides temporary screenshot output; `PLAYWRIGHT_MODULE` remains supported. See [development](docs/development.md) for Python/Pillow and video requirements.
- `npm ci` applies declaration-only `patch-package` patches for `three-stdlib@2.36.1` and `@types/three@0.186.0` (SVG/TGA and exact optional-property compatibility). Preserve `skipLibCheck: false`, and the application's `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` checks. The patches change no runtime code.
- Dev and preview use `/damien-portfolio/`. Public URLs must use `import.meta.env.BASE_URL`; preserve Vite's React/React DOM/Three dedupe and prebundling settings.

## App boundaries
- `src/main.tsx` uses StrictMode; `src/App.tsx` mounts the lazy full-viewport `CityWalkthrough` and persistent `BackgroundMusic` controls. `PortfolioSections.tsx`, `Section.tsx`, and `KeyboardViewer.tsx` are not mounted.
- `App` starts with `EntryChoice` (3D / 2D), honoring opt-in `damienckj-entry-mode` and explicit `?mode=entry|2d|3d` URLs. Entry/2D must not mount Canvas or prepare audio/models. `Portfolio2D` adapts the supplied HTML using canonical profile data and the public-only generated project catalogue (`scripts/build_portfolio_2d.mts`, run before dev/build); native scrolling and a modal mobile floor picker stay local to that viewport. Run `node --import tsx scripts/verify_portfolio_modes.mts` after building.
- After choosing 3D, `App` owns one eager `LoadingScreen` across the lazy runtime import and asset preparation; its weighted milestone progress/checklist reflects actual completion, not a demo timer. Startup prepares city/journey, lobby, cabin, all four room packages, both portrait layers and project posters, and waits for the first rendered city frame. Hand off immediately once preparation is complete, without an artificial delay. Audio bytes buffer silently; sound choice/playback waits for the handoff. Preserve finite demand rendering, abort/StrictMode cleanup, truthful unavailable states and Retry. Run `node --import tsx scripts/verify_startup_loading_browser.mts` after building; `STARTUP_TEST_DEV=1` checks StrictMode.
- Portfolio/Observer/contact text belongs in canonical `src/data/portfolio.json`; `src/data/portfolio.ts` validates it and adds generated portrait metadata. Python and Node read JSON directly, without VM/regex extraction of app source; content provenance hashes canonical JSON bytes. Project and observatory exhibit content has separate JSON sources in its model directory.
- The downloadable CV is an uploaded file in `public/cv/`, served unchanged; `src/data/cv.json` only lists its file names (first = main link, a PDF is required for printing). `scripts/verify_cv.mts` checks the folder matches the list. See [development](docs/development.md#downloadable-cv).
- Amplifii / AMPLYFII (Ampress) is NDA-covered. Publish only its general influencer-marketing purpose, unreleased status and broad product-development/teamwork contribution. Do not add specifications, implementation details, detailed features, source references or project-specific technical skills evidence. Keep catalogue, timeline, native card text and browser exports aligned; `node --import tsx scripts/verify_public_links.mts` checks this boundary.
- The document does not scroll; 2D uses its own scrolling viewport. In 3D, `useScrollTimeline.ts` maps viewport-local gestures to a reversible journey and yields input during departure/room visits.
- Keep the shared Canvas demand-rendered with capped DPR. Animate only active/visible areas, invalidate while changing, and settle when idle; see [runtime guidance](src/components/city/AGENTS.md).
- Tailwind v4 coexists with unlayered custom CSS. Check `src/index.css` and `city/city.css` when utilities appear ineffective.
- Level 02 Skills, Level 03 Projects and Level 04 Experience share `ProjectCardFocusControls`: desktop case-file sidebars and a mobile chapter header/progress bar, reading panel, fixed navigation dock and native chapter-picker dialog. Preserve translucent live-room backgrounds, saved room view on return, and source-backed section content. Level 01 `ObserverProfile` uses the Identity / Portrait / Record layout with the existing `PixelPortrait` color-reveal trail. Detailed behavior and focused browser commands are in [runtime guidance](src/components/city/AGENTS.md).
- Viewport size determines responsive layout, not device identity. Detect hover/pointer capabilities or the current pointer event for mouse/touch behavior; a narrow desktop window must retain mouse hover and keyboard interactions.
- Interaction audio is click-only; hover/focus are silent. DOM controls default to `system-click.mp3` via `SoundEffectsProvider`; environment labels/accessibility controls use `data-sound-effect="environment"`. Native environment picks use `useSoundEffects().environmentClick()`, with room scene clicks centralized after the drag guard; system shortcuts use `click()`. Avoid double-playing, keep disabled/drag/continuous movement silent, and preserve gesture unlocking, saved effects mute/volume and cleanup. See [sound-effect convention](docs/sound-effects.md); check with `node --import tsx scripts/verify_interaction_audio.mts`.

## Model ownership
- `assets/*/AGENTS.md` contains scoped instructions beside each model. Read [asset rules](assets/AGENTS.md) and the affected model's guide before modifying Blender files or generated exports.
- Authored masters, integration copies, and browser packages are different outputs. Routing is defined by `assets/journey/room-destinations.json`; loading/alignment metadata is generated in `public/models/journey.json`.
- Project video originals are local/Git-ignored under `assets/project-hallway/videos/originals/<project>/`; prepared videos, H.264 compatibility copies and posters are tracked in `public/videos/`, copied by Vite to `dist/videos/`. Do not place video files at the repository root. See [video ownership](assets/project-hallway/videos/README.md); `scripts/verify_project_video.mts` checks organization and browser assets.
- Do not hand-edit binary offsets, strides, or hashes in generated packages. Regenerate related files together; standard GLB export does not preserve the point/line representation.
- Keep model redesigns scoped: preserve previously completed surroundings, NPC visibility/actions and journey connections unless their replacement is explicitly requested. In the city, tower rebuilds must retain the detailed orbital sky, 18 outdoor NPCs, geographic Earth hologram and sealed working entrance; ownership and regression commands are in `assets/cyber-city/AGENTS.md` and `assets/journey/AGENTS.md`.
- Human-facing documentation is indexed by [README.md](README.md): [development](docs/development.md), [architecture](docs/architecture.md), and [planned features](docs/roadmap.md).
